# Hosted apps sign people in to other services (OAuth)

- `[server]` Manifest `"oauth"` providers; the suite keeps the client secret (encrypted, set in Admin › Apps or for a draft
  on the Build page), runs the sign-in with state + PKCE at one callback, `/v1/apps/oauth/callback`, and keeps each
  person's token (refreshed when it runs out).
- `[server]` App SDK: `ctx.oauth.fetch/token/status/disconnect`; screen host paths `/__freeflow/oauth/<id>` (status,
  `/start`, disconnect). A draft uses the install's client only when the provider's addresses are unchanged.
- `[server]` Per provider, `"tokenAuth": "basic"` (Notion, Reddit) and `"authorizeParams"` (Google's
  `access_type: offline`) cover services that differ from the usual pattern.
- `[server]` A draft's dev install may now reach the egress hosts an admin approved for the installed version.
- `[web]` `[desktop]` Admin › Apps "Sign-in to other services" form; Build page Sign-in tab; the Build preview's popups
  leave the sandbox, as the installed tab's already did.

## Feature

- **Apps can connect your accounts on other services.** An app built in FreeFlow can now ask you to sign in to a service
  such as GitHub, Google or Notion and then work with your account there. An admin sets up the service once in Admin › Apps; FreeFlow keeps
  its secret, and each person connects their own account from the app.
